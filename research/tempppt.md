# tempppt.md · 三大任务（模块化深化版）

> 抽离自 `ppt.md` 的 Slide 2/3/4，对方法做**模块化**重述：每个任务都拆成
> **① 感知 → ② 决策 → ③ 执行 → ④ 安全护栏** 四个可复用模块（全系统共用同一套，换任务只换模块内的"模型库 + 度量"）。

---

## Slide 2 · 任务一 · 时序预测 (Forecasting)

**背景**：新产线 / 新传感器要 zero-shot 长视野预测；单一 TSFM 跨域饱和度差异大
（Weather 上 Chronos-2 是 SOTA，Exchange/ECL 上落后专家模型 35–44%）；工业看 **CRPS（要置信区间）** 甚于 MAE。
**输入 / 输出**：少样本（N=10–100）单/多变量序列 → 未来 H 步点预测 + 概率区间。

| 模块 | 本任务实例 | 作用 |
|---|---|---|
| **① 感知（Curator）** | 诊断 趋势 / 季节 / 平稳性 / 噪声 / 长度 → 序列画像 z | 判断"这条数据像什么" |
| **② 决策（Planner）** | walk-forward 验证（用训练尾部模拟未来）→ 估各模型 CV-MAE；**强阈值门控** | 判断"该不该换模型" |
| **③ 执行（Router）** | 模型库 = Chronos-2 / Chronos-Bolt / TimesFM-2 / Moirai(2) / TiRex / Toto / Time-MoE / Sundial / Timer-S1 + ARIMA/naive | 选中模型出预测 + 区间 |
| **④ 安全护栏** | 偏离候选**只限强 TSFM**；naive/arima 仅作 base 安全网（避免小验证窗"假赢"）| 永不伤默认 Chronos-2 |

**工程结论（绝对 / 上界）**
- 默认 Chronos-2 在 **25%** 的 cell 上已是最优（基于 6 数据集先验）→ 大多数情况守默认即可。
- **理论路由增益上界 ≈ 19% rel-MAE**（oracle 对 Chronos-2，"完美选模型"天花板）。
- 系统实测：与 Chronos-2 **持平**（不伤默认），偏离仅在高把握（强 margin）时发生。

## Slide 3 · 任务二 · 时序分类 (TSC)

**背景**：故障类型识别 / 质量分级，**few-shot 是常态**（每类 3–10 样本，新产线冷启动）。
**输入 / 输出**：few-shot 单/多变量 → 类别。

| 模块 | 本任务实例 | 作用 |
|---|---|---|
| **① 感知（Curator）** | cell 级画像：每类样本数、类数、长度、通道、复杂度 | 量"任务难度 + 样本是否够" |
| **② 决策（Planner）** | 训练集内 CV（LOO / k-fold）估各分类器准度；**N<7/类 → 强制兜底默认**（CV 不可信）| 判断"敢不敢信 CV" |
| **③ 执行（Router）** | 模型库（10 个）= Rocket / MiniRocket / WEASEL / Catch22 / MOMENT(1nn/lr) / Mantis(1nn/lr) / DTW / Euclid | 选中分类器出类别 |
| **④ 安全护栏** | margin 门控（候选须显著超默认才换）+ 异常回退 Rocket | 永不伤默认 Rocket |

**工程结论（绝对 / 上界，基于 22 数据集先验）**
- 默认 Rocket 绝对准确率 **86.1%**；**oracle 上界 90.2%** → **理论路由增益上界 +4.1pp**。
- **模型库大小决定头寸**：5 模型时 Rocket 在 **71%** cell 最优；**10 模型时降到 38%**（MiniRocket/WEASEL 接管）。
- → **工程含义：扩模型库是提升路由头寸最直接的手段。**

## Slide 4 · 任务三 · 机械诊断 (Anomaly + RCA)

**背景**：从振动 / 电流 / 温度时序判断机器问题，不只"有没有异常"，还要 **根因 + 严重度**。
**输入 / 输出**：多通道时序（+ 可选维修文本）→ 异常标志 + 故障类型 + 严重度 + 根因解释。

| 模块 | 本任务实例 | 作用 |
|---|---|---|
| **① 感知（Curator）** | 12-d 诊断（趋势 / 季节 / 平稳 × 3 置信源，含 outlier / variance）| 提取故障统计征兆 |
| **② 决策（Planner）** | 异常打分（规则 + 残差检测）→ 故障类型先验；判"是否进入根因推理" | 决定走规则还是 LLM |
| **③ 执行（双路）** | **规则基线**（滑窗方差 / IQR / ADF）兜底 + **LLM Agent** 结构化根因（只诊断+解释，不预测）| 出根因 + 自然语言 |
| **④ 安全护栏** | 规则基线永远在；LLM 受**检索-grounded** 约束；OOT（未知故障）→ abstain head | 防 LLM 幻觉、不漏未知故障 |

**工程结论（绝对 / 双面）**
- 合成 4-class 故障：默认 Rocket 绝对 **50.6%**，oracle 上界 52.0%（**理论增益上界仅 +1.4pp** → 头寸小，宜守默认）。
- 根因（RCA）：结构化 Agent 比无结构 LLM **+40pp**；但对工程规则基线 **−37pp** → **保留规则基线，LLM 提供可解释根因而非取代规则**。
- OOT（未知故障）检测：abstain head + 强 LLM + 数据集先验 三路叠加可达 **100% recall**。

---

> **三任务同构**：四个模块（感知 / 决策 / 执行 / 安全护栏）完全复用，
> 换任务只替换 ③ 的"模型库"与对应度量（MAE↔准确率↔故障召回）。
> 贯穿的工程铁律：**系统永不显著伤害默认模型**——最差等于直接用 Chronos-2 / Rocket / 规则基线。
